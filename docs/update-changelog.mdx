## Safe update procedure

1. Back up the avatar and the project outside the project.
2. Check the currently installed Real Sweat System version.
3. Import every Base and Effects module you own at the same new version over the existing files. The import order does not matter.
4. Do **not** uninstall the old version or delete the `RealSweat` object or `Assets/CookiTools/Generated` first.
5. Open `CookiTools → RealSweatSystem → Setup／Uninstall` and press **[Install / Update]** once for each avatar. **Apply to FX alone does not do this update.**
6. Save the scene, check the Console, and test the avatar in Play Mode and with an avatar build before upload.
7. Before you upload, make sure this PC has the purchase activation for every installed module ([Purchase Activation](./license-activation.mdx)). Updating does not ask for it, but an upload without it leaves those effects out.

If the versions are mixed, the Setup window asks you to re-import them at the same version and does not install.

Updating from 2.0.x to 2.1.0 does not need **[Install / Update]** again: importing over the old files is enough. Heart Rate Link, and hiding the floor stains with **Sweat Display**, come with **[Install / Update]**. See the [Update Quick Guide](./update-guide.mdx).

For an update from 1.x to v2.1.0, read [Updating from 1.x](./quick-start.mdx#updating-from-1x) first: the look values of earlier sweat materials are set to the new defaults, and the first press of **[Install / Update]** stores new per-avatar data.

For removal, clean reinstallation, or changing between Base, Effects, and Full Pack, follow [Uninstall, reinstall, or change modules](./troubleshooting.mdx#uninstall-reinstall-or-change-modules).

## v2.1.0 {/* #v210 */}

v2.1.0 (2026-11-16) adds Heart Rate Link (experimental, optional), 1.x Pattern Density and purchase activation in the Linux and macOS editors, and fixes a number of problems.

To update, import every Base／Effects module you own at v2.1.0 over the old files. Updating from 2.0.x does not need **[Install / Update]** again. Heart Rate Link, and hiding the floor stains with **Sweat Display**, come with **[Install / Update]**. To update from 1.x, follow [Updating from 1.x](./quick-start.mdx#updating-from-1x).

- **Heart Rate Link (Experimental; optional, off by default):** Auto Mode's sweat follows the heart rate (BPM) that a heart-rate app sends to VRChat over OSC. Turn on **Heart Rate Link** under **Auto Mode Sensitivity** on the Setup window's first screen and press **[Install / Update]**. When it is off, nothing is added to the avatar; when it is on, no synchronized bits are added. It was tested in Unity; it has not been tested in game with a heart-rate app yet. See [Heart Rate Link](./usage/heart-rate-link.mdx).
- **1.x Pattern Density:** while the sweat uses the 1.x (Legacy) style, the Tuning's **Surface Droplet Appearance** shows **1.x Pattern Density** (4–64) under **Pattern Density**. Only the 1.x (Legacy) style reads it; raising it gives more, smaller droplets. A new install starts at 22, and an avatar updated from 1.1.x keeps the value it had in 1.x. So two avatars with the same other settings can show very different numbers of Legacy droplets; use this value to match them.
- **Purchase activation (Linux and macOS):** purchase activation now also works in the Unity Editor on Linux and macOS. Until now the activation data was kept only in a Windows-only way, so those editors could not activate. Nothing changes on Windows, and a PC that is already activated does not activate again. Real Sweat System is tested on Windows; it has not been tested in the Linux and macOS editors yet.
- **Clothing Fix:**
  - Pressing **Apply with Material Copies (Recommended)** again (for example after adding another outfit) no longer overwrites copies you changed. A changed copy is kept as it is, only its render queue follows the sweat, and the result names it. To make it again from the original, press **Restore Tracked Clothing Changes**, then apply again. Copies you did not change still follow their originals' changes. Poiyomi's Lock and unlock, values a shader's inspector saves by itself, and properties added by a shader update do not count as changes.
  - **Apply Directly to Original Materials:** when another installed avatar in the open scenes (a duplicate, for example) has applied this mode to the same material, **Restore Tracked Clothing Changes** or **[Uninstall]** on one of them keeps the render queue raised and says so. The last one to restore or uninstall puts the original queue back. An avatar that applies the mode later to a material another install already raised tracks it too. When that other avatar is only in an unsaved scene or in Prefab Mode, the queue also stays raised and the result asks you to save that scene. An avatar that applied it before 2.1.0 gets this when it applies again.
  - For materials applied from 2.1.0 on, a restore puts an original render queue of From Shader back as From Shader instead of a fixed number. Restore and Uninstall no longer lock a Poiyomi original that you unlocked.
  - A renderer that has its own sweat (Sweat on Other Meshes) can no longer be added as clothing: drawing it after the sweat would hide that sweat. A prefab from the Project window in the avatar field now stops without changing anything; use the avatar in the scene (Hierarchy).
- **Uninstall:** before it deletes the generated folder, Uninstall looks for objects that use it in every open scene and in Prefab Mode. A duplicate avatar in another open, unsaved scene no longer loses its sweat files. When leftover generated files without install data are removed and another object uses that folder, the message now names that object.
- **Setup window and [Install / Update]:**
  - When no module could load because the project has script compile errors, the Setup window no longer asks you to re-import; it says to fix the red errors in the Console first (see [The Setup window says the project has script compile errors](./troubleshooting.mdx#script-compile-errors)).
  - The "Parameters may run out" warning also counts the parameters that Modular Avatar Parameters on other objects add at upload, so avatars that used to fail only at upload get the warning first.
  - When the `RealSweat` object was moved or renamed, Setup now says where it is and where to put it back (directly under the avatar root, named `RealSweat`) instead of unrelated errors (a parameter-name collision, install data that doesn't match). A backup kept under EditorOnly does not get this message.
  - Modular Avatar 1.12–1.16 no longer show "Modular Avatar is outdated" on every install. With a version older than 1.12, Setup says that 1.12 or later is needed and stops before changing anything (before, it stopped with an error).
  - Generated folders are made correctly even when the avatar's name ends with a space or a dot, starts with a dot or ends with `~`. When a generated file path would be longer than 240 characters, Setup asks whether to go on before it changes anything (Unity on Windows can fail on paths longer than 260 characters).
  - An avatar installed with **Make Safe Copy (Recommended)** for a body without tangents is no longer asked the same question on every update.
  - When an update fails or is cancelled and is rolled back, the earlier install's generated files are no longer lost when another program (antivirus, for example) holds a file.
  - **[Install / Update]** is faster in big projects (a Rest bake no longer refreshes the whole project).
  - The Write Defaults detection while editing no longer counts Merge Animators under EditorOnly. The upload removes them, so the detection could differ from the build's.
  - With the window in Korean or Japanese, the body's build errors, the parameter-name collision list and the Tuning's **Mouth Parameter** tooltip are no longer in English only.
- **Upload:**
  - After **Force Re-bake on Next Build**, testing in Play Mode no longer uses up the request; the next upload bakes again.
  - An unknown d4rkAvatarOptimizer version no longer stops the upload. A Console warning says that the sweat may be missing or look wrong in that upload and how to exclude the sweat renderers yourself, and the upload goes on.
  - The falling drops' size follows the body's sweat material. Before, it could follow another mesh's sweat material that came first in the hierarchy. Installs get this with the next **Apply to FX** or **[Install / Update]**.
  - On avatars whose armature carries a scale (common in FBX files exported from Blender), the falling drops were drawn tens to a hundred times too big and too fast. Installs get the fix with the next **Apply to FX** or **[Install / Update]**.
  - Turning off **Sweat Display** in the in-game menu also hides the floor stains already on the floor. Installs get this with the next **[Install / Update]**.
- **Sweat on Other Meshes (Experimental):**
  - With the main **Falling Drops** off and a target's **Falling Drops from This Target** on, the Setup window and the Tuning no longer say forever that the install needs refreshing, and **Apply to FX** no longer refuses.
  - An installed target's material list no longer offers its sweat submeshes (picking one stopped the next install).
  - When a target is taken out or uninstalled and its material list matches the prefab again, its prefab override is reverted too, so an update of the avatar package reaches that renderer's materials again.
- **Tuning and the sweat material inspector:**
  - Dragging a slider in the Tuning inspector stutters less.
  - On an installed avatar's sweat material, the inspector's Render Queue field is read-only and says where to change it (in the Setup window's **Advanced Settings > Compatibility (only if needed)**, turn off **Automatic Render Order (Recommended)**, set **Sweat Render Queue**, then press **[Install / Update]**). Before, a change there went back without a word.

## v2.0.2 {/* #v202 */}

v2.0.2 adds the 1.x (Legacy) style, Pattern Density, a separate mask for each material slot and Refraction Strength, and refines a few points of the sweat look.

To update, import every Base／Effects module you own at v2.0.2 over the old files. Updating from 2.0.0／2.0.1 does not need **[Install / Update]** again. To update from 1.x, follow [Updating from 1.x](./quick-start.mdx#updating-from-1x).

- **1.x (Legacy) style:** the Setup window's first page has a third **Sweat Style** picture, **1.x (Legacy)**. Choose it and press **[Install / Update]** to draw the droplets as RSS 1.x did. After install you can also change it in Tuning (**Basic Settings > Sweat Style**).
  - It is the 1.x shader with the effects that were hardly visible taken out, so it looks like 1.1.x. It is lighter than 1.1.x: when others first load your avatar it costs about as much as Anime (a little more than Realistic), and at 0 % sweat it costs the same as the two 2.0 styles.
  - The droplet size follows the avatar's body size, as in 2.0. On some avatars the droplets are therefore a different size than in 1.1.x. Adjust them with **Pattern Density** and **Droplet Size**.
  - With **Droplet Depth** on, droplets near the body's outline rise one by one as round domes, as in the 2.0 styles. This part differs from the 1.1.x Depth look. The rise distances and **3D Detail Precision** work as in the 2.0 styles (the 1.x droplets are larger, so they rise from a little farther away).
  - The quality tiers, the mirror quality, following the Body's Shadow Strength, following Light Limit Changer (LLC) brightness and Refraction Strength work in Legacy too. The falling drops, floor stains and splashes use the anime look.
  - Changing the style puts the look values such as Droplet Size back to that style's defaults.
  - New installs and avatars updated from 1.1.x still start with Realistic.
- **Pattern Density (2.0 styles):** **Pattern Density** (0.5–2, default 1) is back in the Tuning's surface droplet look. Raising it gives more, smaller droplets. At 1 it is exactly the same as 2.0.1.
- **A mask for each Body material slot:** with two or more Body material slots selected, the Tuning's Body Surface Spawn Mask and Body Surface Display Mask have **Separate mask for each material slot** (off by default). Turn it on when a body and a face material on one mesh share overlapping UVs.
- **Raised droplets and toon outlines:** with Droplet Depth on, the lilToon / Poiyomi outline no longer runs across the droplets that rise at the body's edge. The raised droplets now cover the outline.
- **Anime droplet shading:** at conversation distance (about 0.8–1.2 m) the small Anime droplets no longer darken at the bottom so much that they read as bumps on the skin. Large droplets seen up close are unchanged.
- **Dark skin in shade:** in Realistic, droplets and trails on dark skin in shade no longer show as white streaks or dots so much. Light and tanned skin are unchanged.
- **Refraction Strength:** the sweat material inspector's **Lighting** has **Refraction Strength** (−1 to 2, default 1): how strongly a droplet bends the skin behind it. It works in all three styles. 1 is the look so far, 0 bends nothing, and below 0 the skin behind the droplet looks smaller. **Reset Look** sets it back to 1.
- **Darkening rows:** the **Wet Skin Darkening** row, which has no effect in Realistic, is hidden on Realistic materials (Anime is unchanged). 1.x (Legacy) materials show 1.1.x's **Wet Skin Darkening** and **Wet Film Darkening**.
- **README:** the README in the package has a new section, **Hiding sweat behind clothes and the wet skin film**.
- **Motion pendulum:** nobody can grab, pose or push the auto mode's motion pendulum (an invisible PhysBone) any more, so another player touching it no longer raises the sweat. Avatars that are already installed get this from the next upload, without **[Install / Update]**.
- **Reset buttons:** the Tuning's **Restore Category Defaults** and **Reset Advanced FX Values** no longer turn Floor Stains and the Body Steam locations you left out at install back on, which made **Apply to FX** refuse. They now put the values back only.
- **Requirements:** the requirements now name the minimum NDMF version. **NDMF 1.13.1 or newer** is required (installed with Modular Avatar). With an older NDMF the scripts fail to compile and the CookiTools menu does not appear at the top. See [No CookiTools menu at the top](./troubleshooting.mdx#no-cookitools-menu).

## v2.0.1 {/* #v201 */}

- **Fixed uploads that stopped.** With two or more Body material Elements selected, a VRCFury toggle or slider that changes a brightness property on the same renderer (for example `_LightingCap`) stopped the upload with "A build modifier replaced, moved, or merged the exact generated sweat material slot". RealSweatSystem now accepts the sweat material copy that VRCFury makes, and the upload continues. The value VRCFury sets is kept.
- **A build tool that changes a sweat slot no longer stops the upload.** If another build tool deletes a sweat material slot or puts a different material in it, only that part's sweat is left out and the upload continues. One warning appears in the Console and the NDMF window. It says what the slot holds now and how to fix it.
- **Setup window text:** fixed the cut-off Japanese 'Effects to Install' label (now 「導入するエフェクト」), the Japanese Depth caption whose last period wrapped onto its own line, and the cut-off English Auto Mode Sensitivity choices (now "Balanced: recommended, follows motion" and "Sensitive: faster from small movements").
- **First build:** the first upload on a PC can take a few minutes while the sweat shaders compile. Wait even if no progress window appears, and do not close Unity.

To update: import every Base／Effects module you own at v2.0.1 over the old files. Updating from 2.0.0 does not need **[Install / Update]** again.

## v2.0.0 {/* #v200 */}

This update applies to Core, which is shared by the Base Module, Effects Module, and Full Pack. The skin sweat look, the Setup window, and the body steam are new. To update, follow [Updating from 1.x](./quick-start.mdx#updating-from-1x).

### Purchase activation (new)

- A new install, or adding a module, needs purchase activation once on each PC. Open `CookiTools → RealSweatSystem → Purchase Activation` and enter your BOOTH order number or Gumroad license key. Base and Effects are activated separately, and Full Pack covers both. Updating an installed avatar, **Apply to FX**, **[Uninstall]**, and builds are never blocked. See [Purchase Activation](./license-activation.mdx).
- **Uploads:** a VRChat SDK build on a PC without a module's activation leaves out only that module and writes one Console warning for it. The build does not stop. Avatars updated from 1.x also leave the effects out of uploads until this PC is activated; the scene and Play Mode still show them.
- **Activation window language:** the English / 한국어 / 日本語 buttons at the top right of the window switch it. The choice also switches the Real Sweat System windows.
- **Windows only:** purchase activation uses Windows' data protection, so the Mac and Linux editors cannot activate, and uploads from them leave the effects out. (From v2.1.0, activation also works in the Linux and macOS editors, but it is not tested there yet; see [v2.1.0](#v210).)

### Highlights

- **Two sweat styles, picked by picture:** on the Setup window's first screen you click one of two pictures. **Anime** has crisp, cartoon-like droplets with outlines and bright highlights that read well from afar. **Realistic (default)** has many small, clear droplets without outlines; the skin seen through them bends a little, like a lens, and from afar it reads as a wet gloss. New installs and avatars updated from v1.1.x start with Realistic; avatars already installed with 2.0.0 keep the style they chose. The style is one per avatar, and Tuning's **Basic Settings > Sweat Style** changes it later.
- **3D droplets in both styles:** Droplet Depth (tessellation, high load) was rebuilt. Up close, resting and running droplets really rise from the skin and look round from the side, in Anime and in Realistic. At the default precision it draws the same as without it from about 0.7 m away.
- **New skin sweat look:** rebuilt from scratch: resting and running droplets, pore droplets, trails and their fresh sheen, the thin wet film, and the look from afar. Trails run almost straight down, as in v1.1.x. In Anime a running droplet has a rounded head and its trail joins it smoothly, so the trail and the droplet no longer look cut apart. In Realistic the small droplets a running droplet takes from its path no longer pop back right behind it; they return as the trail dries.
- **Droplets that read clearly up close:** droplets are a little larger (Droplet Size 1.6) and their glint is larger and brighter. The material inspector's **Glint Size** and **Glint Strength** (Quick Setup, both 1.5) change the glint; 1 gives a calmer look.
- **Sweat Flow:** a new slider in the material inspector's Quick Setup sets how many droplets run down steep skin, and how far. 1 (the default) is the standard look of each style; 0 keeps the droplets in place, 2 lets most of them run.
- **Dark skin:** droplets show a bright glint instead of grey discs, and the film and trails look much less oily. Pale, normal, and tanned skin look the same.
- **Droplet size from the body:** measured from the humanoid bone lengths of the spine and the legs, never from a bounding box, so hair, hats, accessories, and the pose do not change it. A droplet has the same size relative to the body on every avatar and every mesh (cm or m), and it scales with the avatar. Avatars without humanoid bones use the view position.
- **New Setup window:** the first screen shows the status, **Sweat on** (the body mesh as a field: if the one found is wrong, drag the right mesh onto it; its material shows under it, and **[Change]** opens the material slots in Advanced Settings), the **Effects to Install** check boxes (Falling Drops, Floor Stains, Breath, Body Steam) and **Skin Sweat: Wet Skin Gloss**, the style pictures, the **Look** pictures (**Flat** / **Depth (High Load)**), the **Load** buttons (**Low Load (Recommended)** / **Standard**), Auto Mode sensitivity, and **[Install / Update]**; the other options are under **Advanced Settings**, whose **Effects** group holds where the body steam rises and the intensity menu. **Depth (High Load)** turns on Droplet Depth, 3D Particles, and the drop splash together and shows **On from the Start** under it; a new install starts with **Flat**, without the splash. The caption under the Depth picture says the droplets rise when seen up close and from the side, and that Droplet Depth starts off and is turned on in the in-game menu unless On from the Start is ticked; while it is off, an info box shows that menu. The pictures keep one size in any window, and a short window scrolls. **Lightweight** is picked in **Advanced Settings > Quality & Load**. The tabs are Install / Troubleshooting / Uninstall, results appear right under the button you pressed, and the longer steps show a progress bar.
- **New body steam:** instead of one big puff from a point, soft smudged steam rises slowly from a wide area around each spot (upper chest, shoulder line, front of the thighs and ankles). It follows the body when you walk, shows in worlds without a depth texture, does not glow in dark worlds, and uses fewer particles (a default install: at most 168 → 95).
- **New falling drops and splash:** smaller drops that stretch as they fall and a short splash of round droplets, in both sweat styles and in 2D and 3D particles. 2D now has a splash too; the ring-shaped 3D crown is gone. Floor stains keep the soft shapes of 1.1.3 and only darken the floor.
- **3D body steam and breath in the performance rank:** they look the same, and their Mesh Particle Active Polys in the VRChat performance rank are far lower (a default install's steam and breath: 96,000 → 92).
- **Much lighter:** the shader compile freeze other players get when they first load this avatar is about two-thirds shorter than with v1.1.3. The default install at 100% sweat costs about half of v1.1.3's, and sweat at 0% costs far less. See the [measured numbers](./performance.mdx#measured-load).
- **Render queue 2350:** the skin sweat now renders at queue 2350 (v1.1.x: 2455), so it no longer shares a queue with shadow or decal materials drawn over the body, and cutout clothing and hair cover it. If the body renderer has an opaque or cutout material at 2350 or above, Setup asks once whether to lower it to 2349 (recommended) and restores the original queue on uninstall.
- **A screen copy of its own:** 2.0.0 sweat reads the skin from a screen copy with a new name, so it never mixes with v1.1.x sweat on the same screen. Sweat drawn at a queue other than 2350 uses the "(Late Queue)" shaders.
- **Follows Light Limit Changer:** when Light Limit Changer (LLC) changes the avatar's brightness (its minimum and maximum light), the skin sweat follows with the same ratio. It works when the body skin uses lilToon or Poiyomi, with nothing to set up and no extra parameter.

### Other changes

- **Sweat Quality** (was Overall Sweat Amount) picks one of three tiers: Standard, Low Load (Recommended, the default), and Lightweight. The amount of skin sweat is now the same in all three (0.30 at 30%, 1.00 at 100%), so avatars that used Low Load or Lightweight look sweatier than in v1.1.x.
- Each avatar gets its own pattern number, so two copies of the same avatar do not sweat in the same places.
- The new look needs Rest data, which Setup bakes. The material inspector and Tuning say when a material has none.
- **High-Quality Sweat in Mirrors** off (the default): mirrors leave out the small pore droplets and Droplet Depth does not rise there.
- **Remote Low Load** now lightens the skin sweat other players see in every tier. Other players see the body steam at 0.6× density instead of losing puffs.
- The material inspector shows only what the new look reads; the presets became one **Reset Look** button.
- Removed: milk mode, the body normal map's wet effect, the optical LUT, the flow guide map, the Rest pattern rotation, the manual Rest axis modes, and VRC Light Volumes support. The update removes the "VRC Light Volumes" menu toggle and its 1-bit parameter. Old values stay hidden in the materials, and avatar builds no longer upload the retired textures.
- In-game menu names: Breath Puffs → Breath, Steam → Body Steam, Hide Surface Sweat → Hide Skin Sweat, Steam & Breath Intensity → Body Steam & Breath Intensity. Parameters and saved values are unchanged.
- After Uninstall, a prefab instance whose material list matches the prefab again keeps no material override.
- **3D particle body steam:** keeps v1.1.3's amount per tier (0.65× Standard's at Low Load and Lightweight). Puffs drawn at wrong places in the 2.0.0 test builds that only a few testers received (long streaks and stray coloured patches; v1.1.x never had this) are fixed as well. If an avatar uses 3D particles, press **[Install / Update]** or **Apply to FX** once and upload it again.
- **3D particle body steam and breath without a depth texture:** they no longer disappear in worlds whose camera has no depth texture (for example, a world without a realtime directional light that casts shadows).
- **Clear Realistic droplets:** Realistic droplets are now clear and refractive, with no outline: no dark rim, ring, or contact shadow around them, so they no longer read as bumps on the skin. The skin seen through a droplet bends a little, like a lens. Bigger droplets get a small white highlight, trails are clear, glossy streaks without a grey line, and there are slightly fewer of the tiniest droplets. Droplets seen from the front stay as clear as before. Anime is unchanged (crisp outlines and highlights).
- **Realistic at the body's outline:** the thin film's reflection of the sky no longer brightens toward the silhouette, so the light line along the body's outline is less than half as bright. Anime is unchanged.
- **Falling drops, floor stains, and splash:** existing installs get the new look when you press **[Install / Update]** once. The default **Drop Particle Limit (Per System)** goes from 64 to 12, and the strong-movement drops use two thirds of it (8). Only installs still at 64 change. Updating a v1.1.x 2D particle install keeps it without a splash; to use the splash, turn on **Drop Splash** or choose **Depth (High Load)** before you press **[Install / Update]**.
- **Editor code in DLLs:** the editor code now ships compiled, in `Core/Editor/CookiTools.RealSweatSystem.Editor.dll` and, for the Effects Module, `Modules/SweatEffectModule/Editor/CookiTools.RealSweatSystem.Effects.Editor.dll`. Some `.cs` files now hold only a two-line comment. They replace the old scripts of the same name when you update over an older version, so do not delete them.
- **Mixed module versions:** with Base and Effects at different versions, Setup still does not install, but an avatar build no longer stops. It leaves Real Sweat System out of the upload and writes a warning to the Console.
- **Wet Skin Film toggle:** the in-game Sweat menu has a new **Wet Skin Film** toggle, on by default. It turns the thin wet film between the droplets and its gloss on and off, the glisten from afar included, and costs 1 synchronized bit. Setup installs it only when **Wet Skin Gloss** is on.
- **Clear droplets from the front:** droplets seen from the front now glint clearly as well.
- **Component icon:** RealSweat components (Tuning, Installer, Custom Steam Point) show the RealSweat icon in the Hierarchy and the Inspector instead of the default script icon. Their icon in the Scene view is turned off once per project; the Scene view's Gizmos menu turns it back on.
- **Ctrl+Z:** **[Install / Update]**, the Tuning's **Apply to FX**, **[Uninstall]**, and the Rest Vertex Data Baker's **2. Bake And Assign** cannot be undone with Ctrl+Z. They delete or make again generated files, so an undo would point at files that no longer exist. Changes you made before pressing them can still be undone with Ctrl+Z. To remove an installation, use **[Uninstall]**.
- **Uninstall:** after **[Uninstall]**, NDMF no longer shows errors in the Console.

### Known limitations

- No sweat is drawn without valid Rest data, for example on a material before Setup or on a mesh changed after the bake (until the next build bakes again).
- Droplet Depth costs more GPU up close and remains a high-load option.
- Sweat 0% and Sweat Display off are not completely free: the screen copy for refraction (GrabPass, about +0.05 ms) remains. Only Hide Skin Sweat costs nothing.
- Remote Low Load: where two surface directions meet (the sides of the torso and the arms, for example), a droplet can look cut straight at its lower edge on other players' screens. It is rare and small.
- Realistic: in folds (above the navel, for example) a small droplet can look split in two, and droplets do not really merge. Its Lightweight places droplets a little differently from its Low Load and Standard.
- RealRain's own realistic raindrops on clothes come with a RealRain update. The rain RealRain puts on the skin already follows the sweat style.

### Going back

v2.0.0 does not include the old look. If you need it, stay on v1.1.3. To go back after updating, restore the backup you made before updating.

## v1.1.0 {/* #v110 */}

### Updating from v1.0.0–v1.0.2

No intermediate release is required. Today, v1.0.0–v1.0.2 installations update directly to v2.1.0 with [the same procedure](./quick-start.mdx#updating-from-1x). The following v1.1.0 migration details still apply to them:

- Older generated data produces a dismissible Scene-view reminder. Press **[Install / Update]** in the Setup window when you are ready.
- Existing sensitivity, Sweat Quality, automatic response, major toggles, and steam locations are mostly preserved. If you edited generated controllers, menus, clips, or particles directly, back them up because Setup can regenerate them.
- Floor Stain `Pooling Chance` migrates from the exact old default `0.25` to the new default `0`. Other custom values are preserved.
- Existing Body Steam mirror appearance is preserved as `Full`; new installations default to `Low`.
- 3D particles and full-quality Body Sweat in mirrors are not enabled automatically. Wet Skin Gloss also follows the installed material state when updating.
- Mixing old and new Base/Effects module versions is blocked during Setup and build. Uninstall is not required.

### New and improved

- Optional high-load 3D Breath, Body Steam, and Falling Drops while retaining the default lightweight 2D particles
- Optional impact splashes for 3D Falling Drops
- The default 3D Falling Drops and motion-fling droplets are 8% smaller than the original scale for a more natural appearance.
- Dedicated particle shaders and Body Steam `Full / Low / Hidden` mirror modes
- Optional Full-Quality Body Sweat in mirrors
- Wet Skin Gloss Setup control, VRC Light Volumes in-game toggle, and **Hide Surface Sweat**. The VRC Light Volumes in-game toggle was removed in v2.0.0.
- Final Body Surface Display Mask with channel, inversion, strength, tiling, and offset controls
- Thin Wet Traces default to `0` in the raw Tess／No Tess shaders and **Reset Visual**. Reset Visual also propagates the reset droplet size and pattern density to managed targets and dependent particle settings. In v2.0.0 the presets were replaced by one **Reset Look** button.
- Experimental multiple Body Material Elements and additional `SkinnedMeshRenderer` targets
- Tuning status, **Manage Targets...**, guided repair/removal, and build blocking for damaged generated slots
- Custom Steam Points with per-point controls and mirrored pairs
- Optional saved synchronized **Steam & Breath Intensity** radial, off by default: 0% = 0.1× opacity, 50% = the existing 1.0× appearance, and 100% = 1.5×. It changes opacity only, does not turn the effects off at 0%, and does not reduce particle or performance cost.
- Optional **Show My Breath in First Person**
- 3×3 Floor Stain variation, brief impact spread, gentler overlap density, and revised drying
- Safer Body auto-detection, broader parameter-collision checks, final Rest/tangent validation, d4rkAvatarOptimizer protection, mixed-module blocking, and Setup rollback
- Build-time compatibility handling for late submesh `baseVertex` changes, preventing surface-sweat fragmentation in confirmed Modular Avatar Shape Changer Delete cases. Compatibility with every mesh-modifying tool or combination is not guaranteed.
- Added an opt-in Falling Drops visibility compatibility setting in the Setup window's **Troubleshooting** tab for Body meshes whose built-in vertex colors can hide the particles. Default behavior is unchanged; it affects Falling Drops and motion flings only.
- Removed unused lighting and soft-particle shader variant axes from optional 3D Water particles without changing their appearance or GPU instancing.
- Menu rename from **Sweat On** to **Sweat Display**; Effects now use a separate submenu

### Important v1.1 limitations

- Experimental additional targets support `SkinnedMeshRenderer` only and add one sweat material and draw cost per configured target.
- Each target requires readable mesh data, valid submesh/material/tangents, a unique animation path, and an unshared generated sweat-material lineage.
- Do not delete, clear, move, replace, or merge a generated RealSweat material or Renderer slot. Use **Manage Targets...** and **[Install / Update]** to repair or remove the target.
- Face tracking, expressions, mesh merging, replacement, and optimization cannot be guaranteed in every combination. Avoid Tess around eyes and lips.
- Floor Stains are collision sub-effects of Falling Drops and require Falling Drops to remain enabled.
- Up to four Custom Steam slots can be active; mirrored pairs use two. Twelve combined built-in/custom emitters is the hard limit, and rate weight above `4.0` is normalized.
- 3D particles and full-quality mirror options increase GPU load. In 3D mode, Body Steam `Low` currently costs the same as `Full`; use `Hidden` for the lowest mirror cost.

For the current synchronized parameter cost, see [Technical Specifications](./technical-specifications.mdx#synced-parameters).
