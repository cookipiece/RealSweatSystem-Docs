# 購入認証

Real Sweat System 2.0.0 では、PCごとに一度購入認証を行います。`CookiTools → RealSweatSystem → Purchase Activation` から認証ウィンドウを開き、BOOTHの注文番号（Gumroadでご購入の場合はGumroadのライセンスキー）を入力してください。認証ウィンドウの言語（English / 한국어 / 日本語）はウィンドウの右上で切り替えられ、選んだ言語は Real Sweat System のウィンドウにも反映されます。

インターネットは認証時と、自動更新のため3週間に一度以上必要です。アバターのビルドやアップロードには不要ですが、認証していないPCからアップロードすると、このツールの効果が外れます。

## 購入ごとに含まれる機能 {/* #modules */}

認証はモジュールごとに行います。

| 購入 | 認証ウィンドウの「含まれる機能」 | 機能ID |
|---|---|---|
| Base Module | Base モジュール | `rss.base` |
| Effects Module | Effects モジュール | `rss.effects` |
| Full Pack (Base + Effects) | Base モジュール、Effects モジュール | `rss.base`、`rss.effects` |
| Full Pack + Game & App Integration & Distribution License（BOOTHのみ） | Base モジュール、Effects モジュール、Game & App ライセンス | `rss.base`、`rss.effects`、`rss.license.game-app` |

- モジュールを別々の注文で購入した場合（例：Baseを先に、Effectsを後で）は、2件目の注文を認証ウィンドウの「別の注文を追加」に入力してください。このPCで認証した注文の機能はすべて合わさります。
- 機能IDは［報告内容をコピー］の内容に表示されます。

## 認証が必要なもの {/* #what-is-gated */}

- **新しいインストール：** Real Sweat System が入っていないアバターで **［インストール / 更新］** を押すときです。
- **モジュールの追加：** **［インストール / 更新］** は、プロジェクトにあるモジュールを常にすべて導入します。アバターにまだ無いモジュールがプロジェクトにある場合（例：Baseだけを導入したアバターがあるプロジェクトに Effects パッケージをインポートした場合）、そのボタンはそのモジュールを追加するため、そのモジュールの認証を求めます。認証が無い場合はインストールを取り消し、何も変更しません。
- **Rest Vertex Data Baker (Advanced) > 2. ベイクして割り当て** には Base モジュールの認証が必要です。通常の導入では Setup が Rest データを自動でベイクして割り当てるため、このウィンドウを使う必要はありません。

認証が無いときは、理由とエラーコード（CT-LIC-…）を示す案内が表示され、［認証ウィンドウを開く］からすぐに認証できます。

## 妨げないもの {/* #not-blocked */}

- **更新：** プロジェクトにあるモジュールがすべてアバターに導入済みであれば、**［インストール / 更新］** は認証を求めません。1.x で導入したアバターも同じです。
- **FX に適用**、**［削除］**、導入済みのアバターの動作
- **アバターのビルドとアップロード：** 購入認証のためにビルドが止まることはありません。アップロードで何が外れるかは次の節にあります。
- 30日間更新できなかった認証は、新しいインストールとモジュールの追加のときだけ更新を求めます。アップロードでは効果は外れません。

## 認証していないPCからアップロードしたとき {/* #uploads */}

VRChat SDK でビルドするとき（Build & Test、アップロード）、アバターに導入されたモジュールごとにこのPCの認証を確認します。認証が無いモジュールはアップロードしたアバターから外れ、認証済みのモジュールはそのまま入ります。例えば Base モジュールだけを認証している場合、肌の汗は入り、Effects モジュールの効果は外れます。

- ビルドは失敗せず、ダイアログも表示されません。外れたモジュールごとに、Console に `Real Sweat System：` で始まる警告が1行出ます。
- シーンのアバター、Play Mode、生成ファイルは変わりません。認証してからもう一度アップロードすると、効果が入ります。
- アップロードで外れる状態のときは、Setup ウィンドウのインストールボタンの上にも同じ案内と［認証ウィンドウを開く］ボタンが表示されます。
- 1.x から更新した場合は、アップロードする前に認証してください。認証する前にアップロードすると、効果が外れます。

確認方法は[アップロードすると汗やエフェクトが外れる](./troubleshooting.mdx#missing-after-upload)にあります。

## Windows専用 {/* #windows-only */}

購入認証は、デバイスキーによってPCに結び付けられます。このデバイスキーは、Windows のデータ保護機能（DPAPI）が Windows のユーザーアカウントごとに暗号化します。Mac や Linux の Unity エディターはこのキーを作ることも読むこともできないため認証できず、Mac や Linux からアップロードすると Real Sweat System の効果は常に外れます。

## PCの台数と解除 {/* #pcs */}

- 1件の注文（またはGumroadでの購入1件）につき、PCを **同時に3台まで** 認証できます。Game & App Integration & Distribution License は10台です。
- 1件の注文で新しく登録できるPCは **30日に5台まで** です。同時に使えるPCの台数に2台を加えた数です（Game & App Integration & Distribution License は12台）。
- ここでの「PC」は、コンピューターと Windows ユーザーアカウントの組み合わせです。Windows を再インストールしたり、別の Windows アカウントで使ったり、認証フォルダー（`%LOCALAPPDATA%\CookiTools\license\`）を削除したりすると、新しいPCとして数えます。
- 認証ウィンドウの［このPCを解除］を押すと、このPCの枠が空きます。PCを入れ替えたり譲ったりする前、または Windows を再インストールする前に押しておくと、PCの台数を節約できます。PC一覧から古いPCを解除できるのは7日に1回です。

## ギフトで受け取った場合 {/* #gifts */}

ギフトで受け取った注文も、ほかの注文と同じく注文番号で認証します。贈ってくれた方に注文番号を聞いて入力してください。難しい場合は、ギフトを受け取ったBOOTHアカウントから、BOOTHメッセージでショップにお問い合わせください。作者がギフトの注文を確認し、注文番号をお知らせします。

## 購入認証のない旧バージョン {/* #legacy */}

購入認証のない v1.1.3 は、旧バージョンのファイルとしてBOOTHとGumroadに引き続き残します。サポートは2.0.0以降のみです。2.0.0 に更新した後で戻すには、更新前に作ったバックアップを使うか、パッケージに含まれる README の「v1.1.3 に戻す」に従ってください。
