# トラブル解決

UnityのConsoleをClearし、問題を一度だけ再現して、**最初のエラー** から確認してください。後に続くエラーは、最初のエラーの結果であることが多いです。

通常動作の記録は、Setup ウィンドウの **トラブルシューティング** タブで **詳細ログを Console に出力** をオンにしたときだけ Console に出ます。問い合わせ用に詳しい情報が必要な場合はオンにしてください。

## 汗がまったく見えない {/* #no-sweat-is-visible */}

まず、何を導入したかを確認します。

- **Effects Moduleだけ** では肌の汗は表示されません。表示されるのは落下する滴、床の濡れ跡、吐息、体の湯気です。
- Bodyの表面の汗には **Base Module** または **Full Pack** が必要です。

Base または Full Pack の場合:

1. Play Modeで **汗の表示** をオンにします。
2. 既定でオンの **自動モード** を一時的にオフにして、**汗 %** を50%以上にします。
3. **負荷を軽減** の **肌の汗を非表示** がオフであることを確認します。
4. Setup ウィンドウで、**汗を付ける場所** の行に意図したボディメッシュが表示され、**詳細設定 > 汗を付ける場所** で肌のマテリアルだけにチェックが入っていることを確認します。
5. Restデータを確認します。新しい見た目は、Rest データが有効な場所にだけ汗を描きます。UV 模様で代わりに描くことはありません。まだインストールしていないマテリアルや、ベイクの後に変わったメッシュでは、Scene ビューに汗が表示されないことがあります。マテリアルインスペクター上部の **Rest データ** 欄と Tuning の **メッシュおよびRestデータ診断** がこれを知らせます。メッシュが変わった場合は、次のビルド（アップロード）時に最終メッシュから再ベイクします。
6. 描画順を確認します。自動描画順では、肌の汗はレンダーキュー **2350** で描画されます。2459以降のボディマテリアルで **そのままにする** を選んだ場合、そのマテリアルが覆う所では汗が隠れます。[Setup がボディマテリアルを2349に下げるか確認する](#render-queue-question)を確認してください。
7. Play Modeを終了し、`CookiTools → RealSweatSystem → Setup／Uninstall` を開いて、**［インストール / 更新］** をもう一度押します。
8. アップロード時に別のツールがBodyを置き換えたり統合したりする場合は、[Unityでは正常、VRChat内だけ壊れる](#it-works-in-unity-but-breaks-only-in-vrchat)へ進んでください。

## Setup ウィンドウに「古いバージョンでインストールされています。」と表示される {/* #installed-with-an-older-version */}

そのアバターは 1.x で導入されています。アバターごとに **［インストール / 更新］** を一度押してください。**FX に適用だけではこの更新は行われません。** バックアップを含む詳しい手順は[1.x からの更新方法](./quick-start.mdx#updating-from-1x)に従ってください。

## Setup ウィンドウが同じバージョンでの再インポートを求める {/* #mixed-module-versions */}

BaseとEffectsのバージョンが異なります。所有している Base／Effects モジュールをすべて同じバージョンで既存ファイルへ上書きインポートしてから、Setup ウィンドウを開き直してください。バージョンが混ざっている間は、安全のためSetupとアバタービルドが停止します。削除は不要です。

## Setup がボディマテリアルを2349に下げるか確認する {/* #render-queue-question */}

肌の汗はレンダーキュー2350で描画されます。ボディのレンダラー（汗を入れるレンダラー）に2350以降で描画される不透明・Cutoutのマテリアルがあると、**［インストール / 更新］** が一度だけ確認します。

- **2349に下げる（推奨）** を選ぶと、マテリアルごとに元のキューを記録してから2349に下げます。**［削除］** すると元のキューに戻します。その間に自分で変更したキューはそのままにします。
- **そのままにする** を選ぶと、汗はそれらの中で最も高いキュー + 1 で描画され、2459を超えません。ボディが2459以降なら、そのままにした汗はそのマテリアルが覆う所で隠れます。
- 選んだ答えはアバターごとに記録します。そのままにした後で選び直すには、**詳細設定 > 互換性** の **［もう一度確認］** を押してから **［インストール / 更新］** を押してください。

マテリアルアセット自体を変更するため、同じマテリアルを使う他のアバター、プレハブ、シーンにも反映されます。変更しないマテリアルについては[対応環境・互換性](./compatibility.mdx#render-queue-and-shadows)を確認してください。

## 汗のメニューが無い・一部だけ無い {/* #the-sweat-menu-is-missing-or-incomplete */}

メニューの項目は、インポートしたModuleとSetupのオプションによって決まります。

- **相手側を低負荷** にはBaseが必要です。
- **エフェクト** とその個別の項目にはEffectsが必要です。
- **体の湯気・吐息の濃さ** は、Setupで任意の同期ラジアルを選択した場合だけ表示されます。
- **水滴の立体感（テッセレーション / 高負荷）** は、水滴の立体感を導入した場合（表現の **立体（高負荷）**、または **詳細設定 > 品質・負荷** の水滴の立体感の切替）だけ表示されます。
- v2.0.0 で **VRCライトボリューム** のトグルは削除され、一部の名前が変わりました: 息 → 吐息、湯気 → 体の湯気、表面の汗を非表示 → 肌の汗を非表示。

期待する項目が無い場合:

1. Play Modeを終了し、すべてのコンパイルエラーを解決します。
2. **Modular Avatar** がプロジェクトに導入され、有効になっていることを確認します。
3. 必要なBaseまたはEffectsのModuleがインポートされ、Full Packの場合はバージョンがそろっていることを確認します。
4. `CookiTools → RealSweatSystem → Setup／Uninstall` を開き、**［インストール / 更新］** を押します。
5. Gesture ManagerまたはPlay Modeのプレビューを新しく開始し、今のメニュー状態を再構成します。

## Tuningの変更が反映されない {/* #tuning-changes-are-not-applied */}

アバタールート直下に生成された **RealSweat** オブジェクトを選び、その **RealSweatSystem Tuning** コンポーネントを使います。

- 汗の品質はマテリアル品質をすぐに変え、汗のスタイルはそのアバターのすべての汗マテリアルにすぐ反映されます。
- 自動反応、カスタムカーブ、落下する滴、飛散パーティクル、吐息、体の湯気には **FX に適用** が必要です。
- **ボディの Shadow Strength に合わせる** は、**［インストール / 更新］** または **FX に適用** の実行時に選択したBodyのマテリアルを読みます。実行時の常時リンクではありません。
- **FX に適用** で導入構成の変更が案内された場合は、調整値を反映する前に **［インストール / 更新］** を押してください。導入するエフェクトの追加・削除は、FX に適用だけでは反映できません。
- 1.x からの更新で **［インストール / 更新］** を押す前に変えた見た目の値は、押したときに新しい既定値に戻ります。見た目の調整は更新の後で行ってください。

## インポートやシェーダーのコンパイルに時間がかかる {/* #import-or-shader-compilation-takes-a-long-time */}

最初のパッケージのインポートでは、Unityがアセットのインポート、シェーダーのコンパイル、Asset Databaseの更新を行うため、時間がかかることがあります。このコンパイル時間は、シェーダーのゲーム内の実行負荷とは別のものです。

- Setupを開いたりPlay Modeに入ったりする前に、Unityのインポートとシェーダーコンパイルの表示が終わるまで待ってください。
- Unityがアセットを処理している間に、Setupを何度もクリックしないでください。
- インポートが完了したと判断する前に、**Consoleの最初のコンパイルエラー** を解決してください。
- 2回目以降のインポートは、Unityがキャッシュを再利用するため速くなることがあります。キャッシュの動作はPCとプロジェクトによって異なります。
- 大きなプロジェクトでは、1.x からの更新後の最初の **［インストール / 更新］** に少し時間がかかることがあり、プログレスバーが表示されます。

## 1.x から更新する

[1.x からの更新方法](./quick-start.mdx#updating-from-1x)に従ってください。要点は、プロジェクトの外にバックアップし、所有しているModuleをすべて同じ v2.0.0 で、旧バージョンを削除せずに既存ファイルへ上書きインポートしてから、アバターごとに **［インストール / 更新］** を一度押すことです。**FX に適用だけでは更新になりません。**

## Play ModeやVRChatで顔が崩れる {/* #the-face-breaks-in-play-mode-or-vrchat */}

以前のReal Sweatの導入が、Write Defaults OFFのフェイストラッキングAnimatorと衝突した場合に起こることがあります。

1. 所有しているModuleをすべて同じ現在のバージョンに更新します。
2. 生成されたAnimator欄やMerge Animator Priorityに加えた診断用の変更を元に戻します。
3. **［インストール / 更新］** をもう一度押します。
4. 顔の表情、汗のトグル、自動モードがすべて一緒に動作することを確認します。

手動で変更したAnimatorの順番を、恒久的な回避策として使わないでください。

## MMDダンス中に表情・リップシンクが動作しない {/* #expressions-or-lip-sync-stop-during-an-mmd-dance */}

1. 所有しているModuleをすべて同じ現在のバージョンに更新し、**［インストール / 更新］** を一度押します。
2. **Write Defaults互換モード** を **自動検出（推奨）** にします。
3. Modular Avatarを更新し、対象の構成で必要な場合はMMD World Supportを有効にします。
4. Play Modeだけでなく、実際に使うMMDワールドで、表情、リップシンク、汗の表示、自動モードを確認します。

外部のFX StateがすべてWD ONの場合、Real Sweat Systemも生成するStateにWD ONを使います。WD OFF、混在、判定不能の構成では互換構成を維持しますが、FXレイヤーの制御はワールドごとに異なるため、すべてのワールドでのMMDの動作は保証できません。

外部のStateがWD OFFのときにRealSweatだけをWD ONに固定すると、ON/OFFが混在したコントローラーに戻ることがあります。対象のアバターやMMD環境が全WD ONのFXコントローラーを必要とすることが明確な場合を除き、固定モードを恒久的な回避策として使わないでください。

## 汗の表示・自動モードが動作しない {/* #sweat-display-or-auto-mode-does-not-work */}

- **汗の表示** が有効であることを確認します。
- 手動で操作する場合は、自動モードをオフにして汗 % を調整します。
- 自動モードの場合は、アバターがHumanoidで、必要なボーン参照があることを確認します。自動モードには、Humanoid AnimatorとMA Bone Proxyが必要です。利用できない場合は手動モードのみ導入されます。
- 生成されたAnimatorやその順番を手動で編集しないでください。
- 新しいバージョンをインポートした後は、**［インストール / 更新］** をもう一度押します。

## 複製したアバターと生成ファイルを共有しているという警告が出る {/* #duplicate-avatar-shares-generated-files */}

まず、調整したいアバターで **［インストール / 更新］** を押してください。選択したアバターの生成ファイルだけが分離されるため、ほかの複製アバターを削除する必要はありません。

同じアバターを別のシーンやプレハブとして複製して保存した場合、閉じている複製は Tuning インスペクターの警告に表示されないため、分離する前に Tuning を変更すると複製の汗の設定も一緒に変わります。**FX に適用** は保存済みのシーンとプレハブも確認し、複製が同じ生成ファイルを使っている場合は何も変更せずにこの警告を表示します。

## ボディメッシュが検出されない

ボディメッシュは自動で見つかり、**汗を付ける場所** の行に表示されます。見つからない場合や違うRendererが表示される場合は、肌側の正しい `SkinnedMeshRenderer` を持つHierarchy内のオブジェクトを使ってください。Projectウィンドウ内の `.fbx` やMeshアセットは使えません。Rendererには、有効なMeshと有効なSubMeshが1つ以上必要です。

実験的な追加対象は **詳細設定** で別に追加し、`SkinnedMeshRenderer` である必要があります。

## 汗が別のマテリアルスロットに表示される

マテリアルが複数あるBodyでは、**詳細設定 > 汗を付ける場所** で肌のマテリアルだけにチェックを入れてから、**［インストール / 更新］** をもう一度押してください。Element 0 が肌だと決め付けないでください。

## 追加対象に修復が必要と表示され、ビルドが停止する {/* #an-additional-target-shows-repair-required-or-blocks-the-build */}

実験的な対象を無効にするために、RealSweatが生成したマテリアルやRendererスロットを削除、空欄化、移動、置換、統合しないでください。生成マテリアル／スロットの欠損や変更は導入状態の破損として扱われ、Tuningに **修復が必要** と表示されます。アバタービルドは対象を黙って省略せず停止します。

1. 生成された **RealSweat** オブジェクトを選択します。
2. **RealSweatSystem Tuning** で **追加対象を管理...** または **Setup ウィンドウで修復...** を使います。
3. 対象を残す場合は、RendererとElementを確認してから **［インストール / 更新］** を押し、マテリアル／スロット、シェル、Restデータ、アニメーション、任意の落下する滴を再作成します。
4. 削除する場合は、一覧の`-`で外してから **［インストール / 更新］** を押します。

Real Sweat SystemのConsoleの案内は、選択したツールUI言語に従います。UnityやNDMFの例外タイトルとスタックトレースは、英語のまま表示される場合があります。

## Tangentが無いという警告

**セーフコピーを作成（推奨）** を選択してください。適切なTangentデータが無い元のMesh向けの、対応済みの代替手段です。

## Unityでは正常、VRChat内だけ壊れる {/* #it-works-in-unity-but-breaks-only-in-vrchat */}

Real Sweat Systemが準備した後に、最適化ツール、リターゲットツール、その他のアップロード時のツールがBody RendererやMeshを置き換えている可能性があります。

- そのツールが選択したBodyを変更していないか確認します。
- 汗の対象SubMeshとマテリアルの対応を保ちます。
- 必要な最終Meshのデータを読み取り可能なままにします。

そのツールに除外機能がある場合は、Real Sweat Systemで使用しているBody Rendererを除外リストへ追加してください。

Bodyを除外する方法が無いツールとの互換性は保証できません。アバターをバックアップし、そのツールを無効にした状態と比較してください。

ツールの設定を変更した後は、Edit Modeで最終的に使うBodyを選んで **［インストール / 更新］** をもう一度押してください。Play Modeと実際のVRChatアップロードの両方で確認してください。Real Sweat Systemは、後で別のビルドツールが行う任意のMesh置換を自動修復できません。

## 既存のPhysBoneが導入後に動かない {/* #an-existing-physbone-stops-moving-after-installation */}

Real Sweat Systemは、自動モード用のPhysBoneとパラメーターを `RealSweat` 配下に追加します。胸のPhysBoneなど、アバターの既存のPhysBoneを変更・削除する仕様ではありません。

1. ConsoleをClearしてPlay Modeに入り、最初のErrorまたはWarningを確認します。
2. ボーン、PhysBone、Animatorレイヤー、パラメーターを統合・最適化する別のビルド時のツールがないか確認します。
3. 動かないPhysBoneとReal SweatのMotion Pendulumが、同じRoot Transform、パラメーター、処理対象として統合されていないか確認します。
4. そのツールにBody Rendererの除外機能がある場合は、Real Sweat Systemで使用しているBody Rendererを除外対象に追加します。Bodyを除外できない場合、そのツールとの互換性は保証できません。

Real Sweat Systemを削除した後も既存のPhysBoneが動かない場合は、Real Sweatが生成した範囲外の変更が残っている可能性があります。バックアップのアバターと比較し、ビルド時に動作するツールを1つずつ切り分けてください。

## Restデータを再生成できない

最終的な元のMeshが読み取り可能で、選択した汗のSubMeshがまだ存在することを確認してください。**［インストール / 更新］** をもう一度押す前に、**汗を付ける場所** の行と **詳細設定 > 汗を付ける場所** を確認してください。

**Rest Vertex Data Baker** は、サポートや上級者向けの保守のための補助ツールです。普段の使用では通常必要ありません。手動で実行する前に[補助ツール](./tools.mdx)を確認してください。

## テッセレーションの水滴が衣装を突き抜ける

`CookiTools → RealSweatSystem → Clothing Fix` を開いて対象の衣装に適用するか、**水滴の立体感（テッセレーション / 高負荷）** をオフにしてNo Tessを使ってください。詳しい手順と注意点は[補助ツール](./tools.mdx)を確認してください。

## Effectsだけの導入でパーティクルが見えない

Effects ModuleはBodyを変更しませんが、放出元としてBody Meshが必要です。**汗を付ける場所** の行に正しいBodyが表示されていること、次の場所でパーティクルの項目が有効になっていることを確認してください。

**汗 → エフェクト**

## 落下する滴や床の濡れ跡が見えない {/* #falling-drops-or-floor-stains-are-not-visible */}

1. **詳細設定 > インストールするエフェクト** で落下する滴が選ばれていることを確認します。床の濡れ跡は衝突サブエフェクトなので、落下する滴も必要です。
2. **汗 → エフェクト** で **全エフェクト**、**落下する滴**、**床の濡れ跡** をオンにします。手動で確認する場合は、自動モードをオフにして **汗 %** を100%にします。
3. 落下する滴は見えて床の濡れ跡だけ見えない場合は、**Default** または **Environment** レイヤーのColliderがあるワールドの床で確認します。
4. 落下する滴や濡れ跡が床より上に浮いて見える場合、アバター内部・足元・衣装・アクセサリー・テスト用オブジェクトにあるBox、Capsule、Mesh ColliderなどのUnity物理Colliderが **Default** または **Environment** レイヤーを使用し、ワールドの床より先に衝突を受けている可能性があります。これはVRC PhysBone Colliderのことではありません。疑わしいUnity Colliderを一時的に1つずつ無効化して切り分けてください。無効化後にワールドの床へ濡れ跡が出るなら、途中のColliderが原因です。
5. 特定のBodyだけで落下する滴がまったく出ず、別のアバターでは動作する場合は、Play Modeを終了して Setup ウィンドウの **トラブルシューティング** タブを開きます。
6. **［修正を適用］** を押してSceneを保存し、Play Modeと **Build & Test** の両方で確認します。
7. この任意の互換設定は、導入済みの落下する滴と体を動かした時に飛び散る滴が、Bodyの内蔵頂点カラーを無視するようにします。Bodyメッシュ、マテリアル、FXコントローラー、床の濡れ跡設定は変更せず、適用前の標準動作も変わりません。
8. 改善しない場合は、問い合わせ前に **［標準に戻す］** を押してください。Renderer、Element、Mesh Import設定、パーティクルのShapeのスクリーンショットを添付してください。

落下する滴だけを診断する目的で、Face Rendererに肌表面のSetupを再実行しないでください。選択した表面の対象が変わってしまいます。

## 最初のビルドは失敗し、2回目は成功する

インポート直後は、シェーダーのコンパイルやAsset Databaseの処理がまだ続いている場合があります。Unityのインポートが終わるまで待ち、**Consoleの最初のエラー** を解決してから、もう一度ビルドしてください。2回目に成功しても、最初のビルドのエラーをすべて無視して良いとは限りません。

## Invalid localAABB がExhaleを示す {/* #invalid-localaabb-mentions-exhale */}

Consoleで無効なlocal AABBが繰り返し表示され、メッセージが吐息のオブジェクトを示す場合:

1. アバターの階層に、無効なTransformや極端なスケール値がないか確認します。
2. 一時的に吐息をオフにして、繰り返し出るログが止まるか確認します。
3. 現在のバージョンを使用してください。

吐息のオブジェクトの範囲エラーと、顔のAnimatorの衝突は別の問題である場合があるため、それぞれ確認してください。

## 削除・再導入・Module構成を変更する {/* #uninstall-reinstall-or-change-modules */}

先にアバターまたはプロジェクトをバックアップしてください。

### アバターから導入内容を削除する

1. `CookiTools → RealSweatSystem → Setup／Uninstall` を開きます。
2. **削除** タブを選択し、アバターを指定します。
3. **［削除］** を押し、Unityの処理が終わるまで待ちます。時間がかかる段階ではプログレスバーが出て、結果はボタンのすぐ下に表示されます。
4. 生成された **RealSweat** オブジェクトが無くなったことを確認します。
5. Base または Full Pack の場合は、メインのBodyと追加対象が生成されたRealSweatのメッシュを参照しておらず、Setupが追加したRealSweatのマテリアルスロットが無くなっていることを確認します。Effectsのみの導入はBodyのメッシュやマテリアルを変更しないため、この確認は不要です。
6. アップロード前にアバターを確認します。

`RealSweat` オブジェクトやコンポーネントだけを直接削除しないでください。削除の処理でボディのメッシュ／マテリアルと外部エフェクトオブジェクトを復元する必要があります。Modular Avatar の非破壊ビルドにより、メニュー/パラメーター/FX は次のビルドで自動的に元へ戻ります。自分で作成した汗マテリアル/スロットには一切触れません。

削除は導入オブジェクトとその子階層、導入専用の生成フォルダーをまとめて削除します。現在のシーン内の別アバターやオブジェクトが共有している生成ファイルは保持し、保存済みの別のシーンやプレハブが同じ生成ファイルを使っている場合や、その確認を完了できない場合は生成フォルダーを残します。元のボディ・衣装・外部アセットは削除しません。元のメッシュを復元できない場合は削除を中止するため、先に参照を確認してください。インストール時に2349に下げたボディマテリアルは、元のレンダーキューに戻ります。

### `RealSweat` オブジェクトだけを直接削除した場合 {/* #manual-delete-recovery */}

Setupは、Body Rendererを汗表現用SubMeshが追加された生成Meshへ置き換え、RealSweatのマテリアルスロットを追加する場合があります。元のMeshと生成Meshの対応は、生成された `RealSweat` オブジェクトに保存されます。このオブジェクトだけを削除すると、メニュー、パラメーター、FXは次のビルドから外れても、Bodyには生成Meshと汗のマテリアルスロットが残ることがあります。

1. **Hierarchy上の `RealSweat` GameObjectだけを削除し、Project内のアセットを削除していない場合に限り**、すぐに **Ctrl+Z** でオブジェクトを戻し、**［削除］** を押します。
2. Undoを使用できない場合は、現在のアバターをバックアップし、`Assets/CookiTools/Generated` を削除しないでください。
3. Bodyの **Skinned Mesh Renderer > Mesh** を、導入直前に使用していた正確なMeshへ戻します。導入前のバックアップまたは元のPrefabを使用し、可能であればMeshプロパティだけを戻してください。
4. 元のMeshを割り当てた状態で **［削除］** を押します。所有情報の復旧案内が引き続き表示される場合だけ、**［インストール / 更新］** を一度押してから、もう一度削除してください。
5. 自動復旧で導入状態を確認できない場合は、同じバックアップを基準に、Bodyの **Materials** 配列と追加対象のRendererも、元の参照・順番・スロット数へ復元してください。

:::warning[Generatedフォルダーを削除した場合、Ctrl+Zで復元できることを前提にしないでください]
[下記のGeneratedフォルダーの復旧手順](#if-the-generated-folder-was-deleted-and-the-body-disappeared)に従い、導入前の正確なBody Meshを先に割り当て直してください。
:::

:::warning[生成されたBody Meshが割り当てられたまま［インストール / 更新］を押さないでください]
`RealSweat_BodyShellMesh` などの生成Body Meshが割り当てられた状態では **［インストール / 更新］** を押さないでください。元の追跡オブジェクトが無い場合、Setupは生成Meshを新しい元Meshとして扱う可能性があります。導入直前のMeshを特定できない場合は、生成アセットを無理に削除せず、バックアップまたは未導入のアバターと比較して復旧してください。
:::

### `Generated` フォルダーを削除した後、Bodyが表示されない場合 {/* #if-the-generated-folder-was-deleted-and-the-body-disappeared */}

BaseまたはFull PackのSetupは、汗用SubMeshを追加した生成Body Meshを `Assets/CookiTools/Generated/<アバター名>` に保存し、Body Rendererへ割り当てる場合があります。このフォルダー、または親の `CookiTools` フォルダー全体を直接削除すると、Bodyが参照しているMeshアセットも失われ、Bodyが表示されなくなることがあります。`Assets/CookiTools/RealSweatSystem` の製品フォルダーだけを削除した場合、生成Meshは通常別フォルダーに残るため、まず所有している同じバージョンのパッケージを再インポートしてください。

1. Play Modeを終了し、現在のアバターをバックアップします。製品ファイルを再インポートした後も、まだ **［インストール / 更新］** は押さないでください。
2. 元のアバターPrefabまたは導入前のバックアップを基準に、Bodyの **Skinned Mesh Renderer > Mesh** をRealSweatSystem導入直前の正確なMeshへ戻します。可能であればPrefabのMeshプロパティだけを **Revert** します。
3. 追加の汗対象Rendererを導入していた場合は、それぞれのMeshも元へ戻します。Bodyまたは追加対象の **Materials** 配列にMissingまたはRealSweatのスロットが残っている場合は、同じバックアップを基準に参照・順番・スロット数も復元します。
4. RealSweatSystemを引き続き使用する場合は、所有しているBase／Effectsをすべて同じバージョンでインポートし、**［インストール / 更新］** を押します。削除する場合は元のMeshを割り当てた状態で **［削除］** を使用します。

正確な元Meshを確認できない場合は、推測したMeshを割り当てたり、MeshがMissingのまま **［インストール / 更新］** を押したりしないでください。導入前のバックアップ、またはRealSweatSystemを導入していないクリーンなアバターと比較して復旧してください。

### 再導入・更新する

1. 使用する現在のパッケージを既存ファイルへ上書きインポートします。1.x から更新する場合は、先に削除したり、既存の `RealSweat` オブジェクトや `Assets/CookiTools/Generated` を削除したりせず、[1.x からの更新方法](./quick-start.mdx#updating-from-1x)に従ってください。
2. BaseとEffectsを両方導入する場合は、まったく同じバージョンにそろえます。
3. `CookiTools → RealSweatSystem → Setup／Uninstall` の **インストール** タブを開きます。
4. **アバター**、**汗を付ける場所** の行、**詳細設定 > 汗を付ける場所**、実験的な追加対象を確認します。
5. **［インストール / 更新］** を押してから、手動モード、自動モード、顔、導入したエフェクトを確認します。

BaseまたはEffectsをFull Packへ拡張する場合は、足りないModuleを同じバージョンでインポートし、**［インストール / 更新］** をもう一度押してください。Full Packから1つのModuleに戻す場合は、先にアバターの導入内容を削除し、不要になったModuleのパッケージファイルをUnityプロジェクトから削除してから、残したModuleで導入し直してください。

:::warning[手動で追加したものは削除されません]
削除の処理は、対応するSetupの外で手動作成したマテリアル、Rendererスロット、Rest Asset、Animationの変更を削除しません。対応していない手動の変更は、バックアップから戻してください。
:::

## Microsoft Defenderがダウンロードを警告・遮断する {/* #microsoft-defender-warns-about-or-blocks-the-download */}

v1.0.0の配布ファイルについて一部の環境で報告されたMicrosoft Defenderの警告は、Microsoftの解析により誤検出と確認され、Microsoft側で該当する検出定義が更新されました。

ただし、DefenderのSecurity IntelligenceやCloud Protectionの更新時期はPCごとに異なるため、一部の環境では以前の警告が一時的に残る場合があります。

- Windows SecurityでSecurity Intelligenceを最新の状態へ更新します。
- BOOTHの購入ライブラリから最新版を再ダウンロードします。
- 警告が続く場合は、検出名、正確なファイル名、Real Sweat Systemのバージョンを確認します。

## よくある使い方のヒント {/* #common-usage-tips */}

### 自分の一人称視点にも吐息を表示する

吐息が装着者自身の一人称視点に表示されないのは、正常な既定の動作です。自分にも表示するには、Tuning の **自分の視点でも吐息を表示** を有効にします。有効なHeadボーンと、MA Visible Head Accessoryを含むModular Avatarが必要です。MA Visible Head Accessoryが見つからないという案内が表示された場合は、VCCでModular Avatarを更新してください。

Gesture Managerだけでなく、VRで結果を確認してください。アバターのスケールによってはパーティクルが顔やカメラに重なるため、既定ではオフです。

### 選択した部位に汗を出さない

汗を出したくない場所は、Tuning の **Body表面の発生マスク** で指定してください。付着水滴・濡れ膜・Tess変位の生成領域を制限します。マスクはUV0を使用するため、BodyのUV0レイアウトに合わせて描いてください。

流れ跡、ツヤ、Tess変位を含む表面の最終結果をその範囲で隠したい場合は、**Body表面の表示マスク** を使います。正確な階調を使うには **sRGB (Color Texture)をオフ** にしてインポートしてください。どちらのマスクも、落下する滴、床の濡れ跡、吐息、体の湯気のパーティクルには影響しません。

### きらめきや流れ落ちる水滴を控えめにする

生成された汗マテリアルのインスペクターで、**クイック設定 > きらめきの大きさ** と **きらめきの強さ** は水滴に映る光（きらめき）を変えます（既定はどちらも `1.5`、`1` に下げると落ち着いた見た目になります）。**クイック設定 > 汗の流れ** は流れ落ちる水滴の数を決めます（`0` では水滴がその場にとどまり、`2` ではほとんどが流れ落ちます）。**標準の見た目に戻す** で、見た目の値を既定値に戻せます。
