# 호환성

## 필수 환경

| 항목 | 지원 조건 |
|---|---|
| Unity | 2022.3 |
| VRChat SDK | Avatars SDK3 |
| 설치 기반 | Modular Avatar 필수 |
| 플랫폼 | PC / D3D11 |
| 아바타 | Humanoid 권장 |
| Body | 아바타 하위의 유효한 SkinnedMeshRenderer |

Quest 단독 실행 환경에서는 지원되지 않으며, 해당 플랫폼에서는 표시되지 않도록 처리됩니다. VRCFury는 필수 의존성이 아닙니다.

## Humanoid와 Non-Humanoid

- Humanoid 아바타에서 MA Bone Proxy 기반 Motion Pendulum을 만들 수 있으면 Manual Mode와 Auto Mode를 사용할 수 있습니다.
- Non-Humanoid 아바타이거나 MA Bone Proxy 기반 Motion Pendulum을 만들 수 없으면 Manual Mode와 **낙하 물방울**, **바닥 물자국**은 사용할 수 있습니다. 이 경우 **자동 모드**, **입김**, **몸 김** 메뉴는 생성되지 않습니다.
- Motion Pendulum은 만들었지만 필수 Head·Chest Anchor를 찾지 못하면 **자동 모드**는 사용할 수 있으며, **입김**과 **몸 김** 메뉴만 생성되지 않습니다.

## 지원 아바타 범위

Real Sweat System은 특정 아바타 전용이 아닌 Humanoid 아바타용 범용 시스템입니다. 일반 설치에서는 Animator를 직접 편집할 필요가 없지만, VCC에서 프로젝트 열기, Unity에서 아바타 Root와 Body Renderer 선택하기, Console 확인하기 등의 기본 조작은 필요합니다.

Mesh, 재질, Animator 및 업로드 과정에서 동작하는 다른 개조 도구의 구성이 아바타마다 다르므로 모든 아바타와 모든 개조 조합의 호환성을 보장하지는 않습니다. Non-Humanoid에서는 위에 안내된 것처럼 일부 기능이 제한됩니다.

## Body Mesh와 Submesh

메인 Body Renderer 한 개를 기준으로 설치합니다. Body에 재질 슬롯이 여러 개라면 **땀 적용 Element**에서 피부가 있는 정확한 Submesh를 선택합니다. v1.1에서는 같은 Body Renderer의 여러 Material Element를 동시에 선택할 수 있습니다.

별도 Body나 Face `SkinnedMeshRenderer`는 v1.1의 **실험적 추가 대상**에 등록할 수 있습니다. 대상마다 별도 땀 마테리얼·Rest 데이터·스케일 정규화·크기·밀도·스폰/표시 마스크·Tess 설정을 유지하며, Effects가 있으면 대상별 낙하 물방울도 선택할 수 있습니다.

GameObject 활성／비활성으로 바디를 교체하는 구성은 각 Renderer／Element를 별도 대상으로 등록해 사용할 수 있습니다. `Renderer.enabled`만 바꾸는 방식의 스왑은 보장되지 않으므로, 사용할 모든 Renderer／Element를 명시적으로 등록하고 실제 아바타 빌드에서 확인하세요.

:::warning[실험적 기능의 범위]
추가 대상은 Read/Write 가능한 Mesh, 유효한 Submesh·Material·Tangent, 고유한 GameObject/애니메이션 경로와 다른 대상이 공유하지 않는 고유한 땀 마테리얼 연결이 필요합니다. Face Tracking·표정·Mesh 병합·교체·최적화의 모든 조합은 보장되지 않으며, 눈·입술 주변 Tess는 권장하지 않습니다.
:::

업로드 과정에서 Body Mesh를 합치거나 교체하는 도구를 사용한다면 다음 조건을 유지해야 합니다.

- 땀 대상 Submesh와 재질의 대응 관계가 유지될 것
- 최종 Mesh 데이터에 접근할 수 있을 것
- 설치 후 땀 대상 Submesh가 제거되지 않을 것

Unity에서는 정상인데 VRChat에서만 깨지는 경우, 업로드 단계에서 다른 도구가 Body Renderer 또는 Mesh를 교체하지 않는지 확인하세요.

설치된 추가 대상을 끄기 위해 생성된 RealSweat 마테리얼이나 Renderer 슬롯을 직접 삭제·비우기·이동·교체·병합하지 마세요. v1.1은 이를 설치 손상으로 감지해 **복구 필요**로 표시하고 빌드를 중단합니다. Tuning의 **추가 대상 관리...**에서 목록을 수정한 뒤 전체 Setup을 실행하세요.

## Tangent

Body Mesh에 Tangent가 없다면 Setup에서 **안전한 사본 생성 (권장)**을 사용하세요. Tangent 처리 결과가 다른 Mesh 변환 도구에 의해 다시 교체되지 않도록 확인해야 합니다.

## Write Defaults · MMD · Face Tracking

v1.1.0은 아바타 FX의 Write Defaults 구성을 자동으로 판정합니다.

- **자동 감지 (권장)**는 RealSweat 외부 FX State가 모두 WD ON일 때만 생성되는 RealSweat 레이어도 모두 WD ON으로 구성합니다.
- WD OFF, ON/OFF 혼합 또는 판정 불가 환경에서는 v1.0.1의 Driver ON / Output OFF 호환 구조를 유지합니다.
- 빌드 시 NDMF로 최종 병합된 FX를 다시 검사하고, 감지 결과에 맞춰 RealSweat의 WD 구성을 조정합니다.
- v1.0.x에서 업데이트했다면 보유한 모듈을 모두 같은 v1.1.0으로 임포트한 뒤 전체 Setup을 한 번 실행하세요.
- Setup이 생성한 Merge Animator Priority 또는 Animator 항목을 수동으로 바꾸지 마세요.

RealSweatSystem은 자신이 소유한 State만 변경합니다. 아바타 또는 다른 도구가 추가한 FX State의 Write Defaults 설정은 변환하지 않습니다.

### MMD 월드 호환성

아바타의 FX Animator에 Write Defaults OFF State가 포함되어 있으면, 월드의 FX 레이어 제어 방식에 따라 일부 MMD 재생 중 표정·립싱크 또는 Real Sweat System이 정상적으로 작동하지 않을 수 있습니다. Write Defaults ON/OFF가 혼재된 아바타 역시 호환성을 보장하지 않습니다. 이는 모든 WD OFF 아바타가 MMD에서 미지원이라는 뜻은 아닙니다.

Modular Avatar의 MMD World Support는 FX Animator의 제2·제3 레이어를 비활성화하는 방식의 MMD 월드에 맞춰 레이어 배치를 보정하는 기능입니다. 모든 MMD 월드 또는 모든 Write Defaults 구성과의 호환성을 보장하는 기능은 아닙니다.

실제로 사용할 MMD 월드에서 표정·립싱크·땀 표시·Auto Mode를 확인하세요.

## Modular Avatar, VRCFury와 최적화 도구

Modular Avatar는 필수입니다. VRCFury, Avatar Optimizer와 기타 비파괴 도구는 함께 사용할 수 있지만, 업로드 시 Body를 최종적으로 교체하는 기능이 있다면 위의 Mesh 조건을 지켜야 합니다. v1.1은 빌드 후반의 최종 Rest/Tangent 상태 재검증과 d4rkAvatarOptimizer 보호를 보강했지만 모든 도구 조합을 보장하는 것은 아닙니다.

Modular Avatar Shape Changer／Mesh Cutter처럼 버텍스·Submesh·Material Slot을 변경하는 기능도 완전 호환을 보장하지 않습니다. 추적 중인 생성 마테리얼 슬롯이나 대상 Submesh가 삭제·이동·교체·병합되어 안전하게 대응시킬 수 없으면 v1.1은 잘못된 위치로 계속 빌드하지 않고 중단합니다. 도구를 끈 상태와 비교하고, Scene／Play Mode만이 아니라 VRChat SDK의 **Build & Test**로 최종 결과를 확인하세요.

특정 도구에서만 문제가 발생하면 해당 도구가 Real Sweat 설치 후 Body Mesh 또는 재질 슬롯을 바꾸는지 먼저 확인하세요.

빌드할 때만 Body를 변경하는 도구가 원인이라면 해당 도구에 제외 목록이 있을 경우 Real Sweat System에서 사용하는 Body Renderer를 추가하세요. Body 제외 기능이 없는 도구와의 호환성은 보장할 수 없습니다.

Unity에서 원본 Body Mesh를 직접 변경하거나 교체했다면 모든 Mesh 변경을 끝낸 다음 **Setup — 자동 설치 / 업데이트**를 다시 실행하세요. 빌드할 때마다 다른 도구가 Mesh를 교체하는 구성은 Setup을 다시 실행하는 것만으로 해결되지 않습니다.

## PhysBone 공존

Real Sweat System은 자동 모드를 위해 자체 Motion Pendulum PhysBone과 전용 파라미터를 생성합니다. 기존 아바타의 가슴 등에 설정된 PhysBone을 의도적으로 변경하거나 비활성화하거나 제거하지 않습니다.

다만 Bone, PhysBone, Animator 또는 빌드 데이터를 변경하는 다른 도구와의 조합은 환경마다 다르므로 개별 조합은 Play Mode와 업로드 후 환경에서 각각 확인해야 합니다. 설치 후 기존 PhysBone만 움직이지 않는 상태는 정상 동작이 아닙니다.

## 의상과 입체기능

입체 물방울이 의상을 뚫고 보이는 경우 **RealSweatSystem Clothing Fix**를 사용하세요. 의상의 두께와 Body 사이의 거리에 따라 별도 조절이 필요할 수 있습니다.

## Render Queue와 그림자

<strong>렌더 순서 자동 설정 (권장)</strong>이 켜져 있으면 메인 Body의 땀 재질 Render Queue는 정확히 **2455**로 고정됩니다. 땀이 Body 재질보다 나중에 그려지도록 선택한 Body 재질의 Render Queue를 **2454 이하**로 유지하세요. 실험적 추가 대상은 선택한 원본 마테리얼 뒤에 오도록 `max(2455, 원본 Queue + 1)`을 사용합니다.

Body 재질을 2454 이하로 설정할 수 없다면 <strong>렌더 순서 자동 설정 (권장)</strong>을 끄고, **수동 땀 렌더 큐**를 Body 재질보다 큰 값으로 설정하세요.

:::warning[Render Queue 2500 초과]
수동 땀 렌더 큐를 2500보다 크게 설정하면 Unity의 Transparent 정렬 범위에 들어갑니다. Body보다 나중에 그리는 순서는 유지되더라도 월드 오브젝트나 다른 투명 재질과의 앞뒤 정렬은 카메라와 월드에 따라 달라질 수 있습니다. 특별한 이유가 없다면 자동값 2455를 사용하세요.
:::

**바디 Shadow Strength 따라가기**가 켜져 있으면 실제 그림자 안의 땀도 함께 어두워집니다. Body 재질의 `_ShadowStrength`는 Setup 또는 **FX에 적용**을 실행할 때 복사됩니다.

## 월드 조명색과 환경 반사

피부 표면 물방울과 젖은 광택은 월드의 Directional／Local Light, Ambient SH, VRC Light Volumes와 Reflection Probe 영향을 받을 수 있습니다. 파란색이나 색이 강한 월드에서는 표면 땀도 해당 색으로 물들어 보일 수 있습니다.

v1.1.0에는 밝기는 유지하면서 월드 조명색만 무채색으로 줄이는 사용자 옵션이 없습니다. **VRC Light Volumes** 토글은 Light Volumes 경로만 켜고 끄며 다른 조명·환경광·Reflection Probe 색까지 제거하지 않습니다.

## Face Renderer

v1.1에서는 Face가 별도 `SkinnedMeshRenderer`라면 실험적 추가 대상으로 등록할 수 있습니다. Setup에서 별도 Rest 데이터와 땀 마테리얼을 생성하므로 과거의 수동 Material/Animation Curve 복제 절차를 사용하지 마세요.

Face Tracking·표정·BlendShape·Mesh 최적화 조합은 아바타마다 다릅니다. 눈·입술 주변에는 No Tess를 우선 사용하고 Play Mode와 실제 VRChat 빌드를 모두 확인하세요. 문제가 생기면 Face 대상을 목록에서 제거한 뒤 전체 Setup을 다시 실행하면 메인 Body 설치만 유지할 수 있습니다.
